# A REPENTOGON-compatible layer

REPENTOGON itself cannot run on this engine. It is built for game v1.9.7.12
and the port runs v1.9.7.17: 424 of its 1,167 function signatures match nothing
in this executable, it patches 286 places in the middle of game functions, and
it writes machine code while the game runs, which a statically recompiled image
never executes.

What mods need of it is its Lua surface: about 1,130 functions and 365
callbacks. This folder rebuilds that surface against the game the port runs, a
part at a time. None of it is REPENTOGON's code. REPENTOGON's documentation and
source say what each name does; each one is written again for this executable.
The one file taken as it is, is its table of enum values (`enums_ex.lua`),
copied at packaging time and shipped under its own licence (GPL-2.0).

## How it is put together

| Part | Where | What |
| --- | --- | --- |
| The bridge | `scripts/recomp/host/src/host_rgon.c` | Native. Reads and writes game memory, calls a game function by address (stack words, registers, SSE float arguments), makes a Lua object for a game object, wraps a Lua function so luabridge accepts it, runs the hooks, swaps the engine's callback runner, and keeps `REPENTOGON` visible only to the mods the layer names. |
| The hooks | `RGON_HOOKS` in `scripts/recomp/lift/lift_patches.py`, generated by `tools/hook_table.py` | One slot per wrapped game function (152 of them, round 112). A wrapper tests one byte before anything else, so a function nobody listens on costs that test. |
| Instruction hooks | `RGON_INSN_HOOKS` in `lift_patches.py`, generated by `tools/hook_table.py` | Round 110: a slot at one instruction inside a game function (10 of them, round 112). The handler sees the registers (`B.reg`), the SSE registers (`B.xmm`) and memory as they are there, may change them, and may send control to one of the jump targets the table lists for it. The same one-byte test when nobody listens. |
| The layer | `rgon.lua` and its parts, `api_*.lua` | Lua. Every function and callback. Run by the engine once per Lua state, before the first mod's own script. |
| The mod | `main.lua`, `metadata.xml`, `pack.mjs` | What the game lists. The layer is on when this mod is installed and on, and absent otherwise. |

The parts, in the order `rgon.lua` loads them:

| File | What is in it |
| --- | --- |
| `rgon.lua` | The helpers every part uses, the first hooks (items, trinkets, pickups, HUD, sound, music), sprite layers, the gate. |
| `api_callbacks.lua` | How the layer's callbacks are run (REPENTOGON's rules: additive values, stop on false, an error in one function does not stop the rest), and the watch on the engine's own runner. |
| `api_lua.lua` | Colours, `WeightedOutcomePicker`, null-item lookup, sprite render flags. |
| `api_data.lua` | `XMLData`, a mod's achievements (and, round 112, what they lock in the game's own content), the layer's save file, `PersistentGameData`, `EntityConfig`, lookups by name, item custom tags, card availability. |
| `api_objects.lua` | Entity fields (status countdowns and the like), `EntitySlot`. |
| `api_game.lua` | Bomb, tear and laser fields; the methods that are a call into the game. |
| `api_player.lua` | The player's fields, each with the amount it has moved by in this build. |
| `api_sprite.lua` | Animation data, layers, frames and null frames of a sprite. |
| `api_misc.lua` | Timers, `Isaac.IsInGame`, completion marks of a mod's characters, `Console`, `os`. |
| `api_innate.lua` | Innate items (`AddInnateCollectible` and its family). |
| `api_extra.lua` | Round 109: `GetActiveMaxCharge`/`GetActiveMinUsableCharge` of a slot, `RoomTransition`, `EntityLaser:SetInitSound`, `MultiShotParams`. |
| `api_hooks.lua` | The callbacks that are a handler before or after a game function, and (round 110) the ones an instruction hook fires: MC_EVALUATE_STAT, MC_PRE/POST_PLAYER_USE_BOMB, MC_POST_FIRE_SPLIT_TEAR. |
| `hook_slots.lua` | Generated: each hooked function's slot and what it pops. |

Most of the layer is Lua and ships as a mod, so adding a function is a new mod
archive, not an engine release. A new **hook** is the exception: it changes the
recompiled game and needs an engine build.

```sh
node scripts/recomp/rgon/pack.mjs .scratch/rgon/repentogon.zip
```

## What a mod sees

A mod reads `REPENTOGON` as nil unless the layer names it (`ALLOW` at the end of
`rgon.lua`). A mod that sees `REPENTOGON` takes its REPENTOGON-only paths and
drops its own fallback code, so a gap in the layer would be a Lua error or a
feature that silently never runs. A mod is added to the list once what it uses
is covered and that has been checked by running it.

The names the layer adds to shared tables (the enums, new methods on the
game's classes, `PlayerManager`, `XMLData`, `os`) are there for everybody.

`?ISAAC_RGON_ALLOW=<folder>,<folder>` in the address lets more mods in for a
test, `=*` every mod. `?ISAAC_RGON=0` keeps the layer from loading at all.

Three kinds of name, and how to tell them apart:

- **Implemented** (`REPENTOGON.Implemented[name]`): does what REPENTOGON's
  does, on this build.
- **Accepted, not supported** (`REPENTOGON.Unsupported[name]`): a mod may call
  it and nothing is done, because the feature is a change inside the game that
  the layer does not make yet (`Isaac.ReworkCollectible`, a backdrop or a boss
  colour a mod defines, completion marks of the game's own characters). Said
  once in the game's log: `[REPENTOGON] accepted, not supported in the browser:
  ...`. These exist so that a large mod can load at all; they are gaps, and
  are counted as gaps.
- **Absent**: nil, as without the layer. A callback nobody fires is said once
  per mod: `[REPENTOGON] not implemented: callback MC_X ...`.

## Achievements a mod names

A mod's `achievements.xml` (in `content/`, or `content-repentogon/`, which the
layer reads first) defines achievements by name; they get the numbers after the
game's own (0x282 up), in load order, and the layer keeps whether each is
unlocked. `PersistentGameData:TryUnlock`/`Unlock`/`Unlocked`, the console's
`achievement <id>` and `lockachievement <id>` work on them, and
MC_POST_ACHIEVEMENT_UNLOCK fires.

Round 112: such a name in the game's own content locks it, as REPENTOGON's does.
The game reads `achievement=` with atoi, so a name gave 0, "unlocked". The layer
writes into each entry what REPENTOGON's ItemPool::Init hook writes into items:
-1 while the achievement is unlocked, its number while it is locked; the game's
own test (PersistentGameData::Unlocked and its inlined copies) then answers,
and nothing asks Lua when the game tests an entry. The entries are a
character's (players.xml `achievement`; `hideachievement` sets its hidden flag),
a collectible's and a trinket's (items.xml), a card's and a pill effect's
(pocketitems.xml) and each of a challenge's `achievements`; they are found once
every mod's content is loaded and written again whenever one of those
achievements changes. The item pools are set up when a run starts, so an item
unlocked in a run is in the pools from the next run (as with REPENTOGON). In the
character menu (a hook after `Menu_Character::UpdateRotations`, every menu
frame) the page of a locked mod character shows only its "Unlocked By" layer and
cannot be started, an unlocked one hides that layer, and (an instruction hook in
the wheel's portrait drawing) a locked character's portrait shows its frame 1.
What is unlocked is kept, per save slot, in the layer's own save file (the save
data of its mod, `REPENTOGON (browser)`, written once after a save slot's
callbacks and after each later change), and read again when a slot is chosen.
`test_ach.lua` checks all of it with the content mod
`tools/test_ach_mod.mjs` makes (see 21.141 in docs/recomp-architecture.md).

## Where an address or an offset may come from

Every address and offset in the layer is this executable's, and says beside it
how it was found. REPENTOGON's own numbers are for another build and are never
used unchecked.

- **reg**: the game's own Lua registration (0x00866960). `addFunction("Name",
  &Class::Method)` compiles to `push <method>; push <"Name">`, so every method
  the game exposes to Lua is there with its address in this build, and every
  data member with its offset. `tools/parse_register.py` turns it into a table:
  62 classes, 923 functions, 149 properties, 284 data members.
  `tools/prop_offsets.py` goes on to read each plain property getter
  (`mov eax, [ecx+disp]; ret`) for the field's offset: 98 more.
- **sig**: a REPENTOGON signature that matches this build exactly once
  (`tools/zhl-resolve.mjs`: 669 of 1,167 do). A unique match is checked before
  it is used: where the game's own registration names the same function the
  two agree (ten of ten compared), and the function's `ret` must pop what the
  signature says it takes (43 of the 45 called so far could be checked that
  way and did; one unique match, a generic prologue, was wrong and was caught
  by its callers).
- **vt**: a slot of a class's virtual table, found through RTTI
  (`tools/vtables.py`). The slot order of the entity classes is REPENTOGON's
  and is checked here against the game's own Lua thunks (`jmp [vtable+0xc]`
  for Update, `+0x14` Render, `+0x20` TakeDamage, `+0x28` Remove) and against
  four functions known by signature.
- **asm**: read off the disassembly (`scripts/decomp/tools/pequery.py`).

**A field is in the layer because this build's code or a test says so, and
for no other reason.** `tools/struct_deltas.py` lines this build's measured
offsets up with REPENTOGON's fields of the same name, and that tells where a
structure has moved: the base Entity, tears, lasers, familiars, NPCs, effects,
pickups, bombs, slots and sprites have not; the **player** has, by 4 to 20
bytes depending on the field (`api_player.lua` has the table); `Game` has
from its item overlay on, and `Manager` from early on. But "the fields on both
sides agree" is not evidence for the field in between: REPENTOGON's own table
has an entity's poison damage at 0x278 where this build's `Entity::AddPoison`
stores it at 0x320, and its place for the urn's souls holds a float here. So
each field is tied to one of:

- the instruction in this build that reads or writes it (an initialiser, an
  `Add*` function), quoted beside it;
- a check in `test_layer2.lua` that sets it through the game's own API and
  reads it back through the layer, or the other way round;
- a measurement by a lab script (`lab_player.lua`, `lab_misc.lua`): a value
  set through the game's API, or the game's own mechanic run, and the object
  searched for what changed.

Fields REPENTOGON names that have none of these yet are listed as left out,
in the file where they would go.

`tools/hook_table.py` holds the list of hooked functions and re-checks every
one against the executable: `python tools/hook_table.py --write`.

## Adding to it

A function over what the game already offers needs no address at all
(`Level:GetDimension`, `PlayerManager`, `EntityNPC:FireProjectilesEx`). A
function that reads a field or calls into the game needs the address found as
above and a check in `test_layer.lua` / `test_layer2.lua`. A callback needs
its game function in `tools/hook_table.py`, an `on("Class::Function", { ids },
before, after)` in `api_hooks.lua`, and its stack cleanup (`ret n`) known,
because a handler that cancels the call has to return for it.

A callback REPENTOGON fires from the middle of a game function (it patches
the code there) needs an **instruction hook** instead: an `INSN_HOOKS` row in
`tools/hook_table.py` (slot from 160 up, the function's address, the
instruction's address, the jump targets a handler may answer, and the
evidence), `--write`, and the printed `RGON_INSN_HOOKS` list pasted into
`lift_patches.py`. The tool checks that the instruction and each target are
instructions of that function; the build checks that the lifted function holds
the instruction exactly once and that each target is a label of it, and fails
otherwise. In `api_hooks.lua` the handler is `at("Class::Function@Point", { ids
}, function(esp, ebp) ... end)`: it runs right before the instruction, reads
and writes registers with `B.reg("esi")` / `B.reg("eax", v)`, the low float of
an SSE register with `B.xmm(n [, v])`, a stack slot as memory (`ebp - 0x474`),
and returns nil to go on or a listed target to jump there (the engine refuses
any other answer). The engine says it can with `B.INSN`; on an older engine
these callbacks stay unimplemented.

`lab_*.lua` are development scripts run with the layer's own access
(`?ISAAC_RGON_LAB=lab_player.lua`), for reading the game's memory while
working out an offset. They are not packed.

## Checking it

```sh
# the layer from inside a running game: every function and callback it has
node scripts/recomp/web/drive_stress.mjs "http://127.0.0.1:8200/play.html?ISAAC_RGON_ALLOW=zz-port-stress" out \
     phases=custom lua=scripts/recomp/rgon/test_layer.lua zips=.scratch/rgon/repentogon.zip
node scripts/recomp/web/drive_stress.mjs "http://127.0.0.1:8200/play.html?ISAAC_RGON_ALLOW=zz-port-stress" out \
     phases=custom lua=scripts/recomp/rgon/test_layer2.lua zips=.scratch/rgon/repentogon.zip

# round 112: a mod's named achievements (with the content mod tools/test_ach_mod.mjs makes)
node scripts/recomp/rgon/tools/test_ach_mod.mjs .scratch/rgon/achmod.zip
node scripts/recomp/web/drive_stress.mjs "http://127.0.0.1:8200/play.html?ISAAC_RGON_ALLOW=zz-port-stress" out \
     phases=custom lua=scripts/recomp/rgon/test_ach.lua zips=.scratch/rgon/repentogon.zip,.scratch/rgon/achmod.zip retries=1

# a mod the layer does not name still reads nil
node scripts/recomp/web/drive_stress.mjs http://127.0.0.1:8200/play.html out \
     phases=custom lua=scripts/recomp/rgon/test_gate.lua zips=.scratch/rgon/repentogon.zip

# what a real mod asks for and does not get: its Lua errors, and the callbacks
# it listens on that the layer does not fire ("[REPENTOGON] not implemented")
node scripts/recomp/web/drive_stress.mjs "http://127.0.0.1:8200/play.html?ISAAC_RGON_ALLOW=*" out \
     phases=tour catalogue=<catalogue> mods=<id> zips=.scratch/rgon/repentogon.zip
```

For a mod too large for the page's import (Fiend Folio is 640 MB), its files
go into a dist's instance tree instead and are read on demand:

```sh
python scripts/recomp/rgon/tools/dev_dist.py <dist> --layer --mod <StageAPI folder> --mod <Fiend Folio folder>
node scripts/recomp/rgon/tools/load_probe.mjs "http://127.0.0.1:<port>/play.html?ISAAC_RGON_ALLOW=fiendfolio-reloaded" out
```

`load_probe.mjs` boots until the mods have loaded and prints each mod's load
result, its Lua errors by place, and what the layer said it lacks.
`?ISAAC_RGON_PROBE=1` answers every missing name with a stand-in so that one
run lists them all (for measuring only). `tools/mods-census.mjs` and
`tools/coverage.mjs` list which installed workshop mods mention REPENTOGON and
which of its names they use.
